Maia 200

B2 B · Tensor-engine-centric — Flexible tensor datapaths

Microsoft's second-generation Azure accelerator, built for inference. A monolithic TSMC 3 nm SoC (over 140 billion transistors) organises compute into tiles and clusters, each level with its own SRAM and DMA, for 272 MB of software-managed on-die SRAM in front of 216 GB of HBM3e.

Compute organization

The tile is the smallest autonomous unit. It contains a Tile Tensor Unit (TTU) for FP8/FP6/FP4 matrix work — including mixed formats such as FP8 activations with FP4 weights — a Tile Vector Processor (TVP) for SIMD work in FP8 through FP32, tile SRAM, a tile DMA engine and a Tile Control Processor that issues TTU and DMA work and synchronises through hardware semaphores.

Several tiles form a cluster that shares a larger cluster SRAM, a cluster DMA engine and a cluster core for multi-tile coordination. Tiles and SRAM have redundancy for yield.

Memory orchestration

Microsoft describes a layered DMA design — tile, cluster and network DMA — so data movement overlaps with compute. Software decides what lives in tile SRAM versus cluster SRAM and when HBM is touched; the NoC supports hierarchical broadcast so one HBM read can feed many tiles.

Interconnect & system scale

The on-chip network separates data and control/synchronisation planes and supports QoS. Off-chip, an integrated NIC provides 1.4 TB/s each way over Ethernet using Microsoft's AI Transport Layer. Four accelerators in a tray form a Fully Connected Quad with direct links; a two-tier topology supports collectives up to 6,144 accelerators.

Programming & scheduling

Compiled through Microsoft's Maia SDK (Triton and PyTorch front ends); the compiler emits tile-control programs, DMA descriptors and semaphore synchronisation.

Why class B2

Dedicated tensor engines with configurable DMA and multi-level software-managed SRAM, handling mixed matrix/vector workloads.
