Maia 300

B2 B · Tensor-engine-centric — Flexible tensor datapaths

Announced in October 2026 for 2027 deployment, Maia 300 moves Microsoft's tile/cluster design to chiplets: a TSMC N2P compute die with four clusters of twelve tiles, two I/O dies and eight HBM4 stacks (288 GB, 18 TB/s), with a 950 W TDP and 96 accelerators per rack.

02Architectural analysis

Compute organization

Each of the 48 tiles keeps Maia 200's recipe — tensor unit, vector processor, DMA engine and local SRAM — and adds a reshaper for layout transforms. Twelve tiles share a cluster SRAM; four clusters are linked by the on-die network. Microsoft adds enhanced MXFP4 support and hardware data-type conversion.

Memory orchestration

Microsoft calls the design a software-defined dataflow architecture: software places data across tile and cluster SRAM, DMA engines and the network. Because memory is spread across chiplets, access is NUMA; on-die SRAM is used as a scratchpad to cut HBM traffic. Coverage also mentions four memory dies whose function is not detailed.

Interconnect & system scale

An on-die AI network controller drives 32 × 400 Gb/s Ethernet ports (3.2 TB/s bidirectional) in a two-tier scale-up network with Microsoft's custom transport; the host link is PCIe Gen 6 x16. A 96-accelerator rack offers 27.6 TB of HBM and ~1.3 EOPS FP4; superpods reach about 12,288 accelerators.

Programming & scheduling

Same Maia SDK model as Maia 200: compiler-generated tile programs and explicit DMA. Maia runs only inside Microsoft's own services.

Why class B2

Flexible tensor datapaths with configurable DMA and software-placed local storage.
