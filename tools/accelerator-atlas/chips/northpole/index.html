NorthPole

C2 C · Spatially distributed — Distributed-memory spatial manycores

IBM Research's NorthPole is an inference chip in which memory and compute are fully interleaved: a 16×16 array of cores, each with 768 KB of unified memory beside low-precision matrix and vector units, on a 22-billion-transistor 12 nm die. There is no off-chip DRAM, no cache and no speculative control — every layer is prescheduled — and four separate on-chip networks move activations, partial sums, weights and instructions.

Compute organization

Each core contains a vector-matrix-multiply (VMM) engine that performs 2,048, 4,096 or 8,192 operations per cycle at 8-, 4- or 2-bit integer precision — precision is chosen per layer — plus a 256-ops/cycle FP16 vector compute unit (VCU) and a 32-ops/cycle FP16 activation-function unit. A core runs eight hardware threads that are synchronised by construction.

The clock scales from 25 to 425 MHz. IBM's rack figures (60 / 115 / 230 peta-ops at INT8 / INT4 / INT2 across 288 cards) correspond to roughly 208 / 400 / 800 TOPS per card.

Memory orchestration

Each core's 768 KB holds that core's weights, its program and its activations; a weight buffer sits next to the VMM and a partial-sum buffer next to the VCU. Across the array that is 192 MB, plus a 32 MB framebuffer for input and output tensors. The model must fit on-chip (or across cards): there is no DRAM interface. IBM reports 13 TB/s of on-chip bandwidth.

Networks-on-chip

Four dedicated NoCs separate traffic by type, with 4,096 wires crossing each core in both dimensions: the Activation NoC reorganises activations between layers ('white matter'); the Partial-sum NoC lets neighbouring cores cooperate within a layer ('grey matter'); the Model NoC streams weights during a layer; and the Instruction NoC delivers each layer's program before it starts.

System & results

NorthPole ships on a single-wide PCIe card whose FPGA bridges PCIe and card-to-card DMA; the host issues three commands (write tensors, run network, read tensors). A 2U server holds 16 cards and a 42U rack 288. On Granite-3.3-8B (W4 / A8), a three-instance rack delivers up to 30,000 output tokens/s at 2k context with 2.8 ms inter-token latency; a 16-card node runs a 3B model at under 1 ms/token, using 672 W of card power.

On ResNet-50, IBM reports about 25× the frames per joule of a 12 nm V100 and about 5× that of a 4 nm H100.

Why class C2 (with C3 traits)

Locally programmed cores with private memory communicating over explicit networks make it a distributed-memory spatial manycore. Its fully prescheduled, stall-free control also places it near the deterministic-streaming subclass.

05Evidence & caveats

Read before comparing
  • 224 MB = 192 MB core memory + 32 MB framebuffer. Peak TOPS are derived from IBM's per-rack figures. Classified C2 (distributed-memory manycore) though its fully prescheduled control also shares C3 traits.
  • Peak TOPS per card are derived from IBM's per-rack peta-ops figures, not quoted by IBM per chip.
  • Card power is reported as 'typically under 55 W' for transformer workloads with a 50 W budget allocation; it is not a TDP.
