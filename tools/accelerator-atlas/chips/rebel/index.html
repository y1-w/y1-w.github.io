REBEL100

B2 B · Tensor-engine-centric — Flexible tensor datapaths

Rebellions' REBEL100, presented at ISSCC 2026, joins four identical Samsung SF4X NPU chiplets with UCIe-Advanced links into one package. Each chiplet carries two clusters of eight neural cores, a shared on-chip memory and one HBM3E stack; DMA engines can pull from local or remote HBM, so the four dies behave as one mesh.

02Architectural analysis

Compute organization

Each 320 mm² chiplet has two neural-core clusters of eight cores. There is no central scheduler: a hardwired synchronisation manager per chiplet coordinates cores, either centrally or autonomously, and cores avoid direct peer-to-peer signalling.

Memory orchestration

Each cluster shares a 32 MB memory split into 16 slices (64 TB/s per chiplet). A DMA subsystem with eight execution engines per die moves data from local HBM3E, remote HBM3E on another chiplet, or the distributed shared memory, at up to 2.6 TB/s per DMA with task-level QoS. Placement is software-driven.

Interconnect & system scale

Every chiplet has three UCIe-A interfaces (16 Gb/s per lane) running a vendor-defined memory-semantic protocol; the on-chip mesh (XY routing, runtime-adjustable QoS) extends across UCIe to 256 routers package-wide. The host sees two PCIe 5.0 x16 interfaces with SR-IOV and peer-to-peer support.

Programming & scheduling

Rebellions' SDK compiles PyTorch/vLLM models; the compiler emits DMA descriptors and synchronisation for the hardware sync managers.

Why class B2

Tensor-engine clusters with software-driven DMA across distributed shared memory.
