Trainium3

B1 B · Tensor-engine-centric — Structured tensor arrays

AWS's third Trainium generation packs eight NeuronCore-v4 cores per device. Each core couples a 128×128 systolic Tensor Engine with Vector, Scalar and GpSimd engines around a 32 MiB software-managed state buffer (SBUF) and a 2 MiB partial-sum buffer (PSUM); the chip has 144 GiB of HBM and 128 DMA engines.

02Architectural analysis

Compute organization

The Tensor Engine is a 128×128 processing-element array clocked at 2.4 GHz. For MX formats it presents a logical 512×128 array (32-element scaling groups), giving four times its BF16 rate. It can also transpose in the background while multiplying.

Vector (1.2 GHz, 512 BF16 elements/cycle), Scalar (activation functions) and GpSimd engines run in parallel with the Tensor Engine and synchronise through semaphores managed by a Sync Engine. Version 4 adds hardware MX quantisation, a fast vector exponential and BF16 accumulation in PSUM.

Memory orchestration

SBUF is organised as 128 partitions that line up with the Tensor Engine's rows; the compiler or NKI kernel author decides which tiles live there and when DMA engines bring them in from HBM. PSUM holds matmul accumulators. There is no hardware cache in this path.

New in v4: indirect (gather/scatter) SBUF and PSUM access in one instruction, read-add-write accumulation into SBUF by DMA, and four DMA quality-of-service classes.

Interconnect & system scale

Twenty collective-communication cores and NeuronLink-v4 links handle device-to-device collectives without occupying the compute engines; Trn3 UltraServers connect 144 chips, with EFA for scale-out.

Programming & scheduling

The Neuron compiler statically schedules each engine's instruction stream; the Neuron Kernel Interface (NKI) exposes SBUF partitions, PSUM and engine instructions directly to kernel writers.

Why class B1

A large systolic tensor array with compiler-managed on-chip buffers and statically scheduled engines.
