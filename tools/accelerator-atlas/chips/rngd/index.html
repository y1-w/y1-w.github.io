RNGD

B2 B · Tensor-engine-centric — Flexible tensor datapaths

FuriosaAI's RNGD ('Renegade') is a PCIe inference card built around a Tensor Contraction Processor: rather than a fixed-size matrix-multiply primitive, its hardware executes general tensor contractions, letting the compiler choose how loops map onto 512 slices of compute and SRAM. The TSMC 5 nm chip has 256 MB of SRAM and 48 GB of HBM3 within a 180 W TDP.

Compute organization

The chip has eight processing elements (PEs) that run independently or fuse in groups of up to four. Each PE contains a control CPU, a Tensor DMA engine and a Tensor Unit of 64 active slices (plus a spare). A slice holds a contraction engine — eight dot-product units with an 80 KB register file and 1,024 accumulators — plus a vector engine for FP32/INT32 work, a transpose engine and a commit unit that writes back with type conversion.

A fetch network with multicast feeds operands from slice SRAM to the contraction engines, so one operand can be reused by many slices without being copied.

Memory orchestration

Every slice owns 512 KB of SRAM (16 banks of 32 KB) giving 32 MB per PE. It supports virtual addressing but is not a cache: the compiler decides tensor placement and DMA traffic from HBM3. Inter-cluster routers move 1,024 bytes per cycle to each neighbour.

Interconnect & system scale

A PCIe Gen 5 x16 card with P2P support; multi-card servers (RNGD Server) scale by PCIe. SR-IOV splits one card into up to eight virtual functions, and PEs can be partitioned into 2, 4 or 8 instances.

Programming & scheduling

Furiosa's compiler lowers models to tensor-contraction loop nests and searches for the best mapping of loop dimensions to slices, PEs and memory tiers; vLLM-compatible serving runs on top.

Why class B2

Dedicated tensor engines with configurable dataflow and explicit SRAM management, flexible beyond a fixed matmul shape.
