MTIA 300

B2 B · Tensor-engine-centric — Flexible tensor datapaths

Meta MTIA 300 is a training-first tensor accelerator designed around distributed recommendation workloads. A reticle-sized compute chiplet integrates 72 active processing elements with dedicated GEMM, vector, indexed-memory and reduction units; 16 Message Engines and two in-package NIC chiplets offload collectives from the PE grid. Its hierarchy comprises PE-local scratchpads, 192 MB configurable global SRAM (LLC or LLS), and 216 GB HBM3E.

02Architectural analysis

Training-first architecture and system partitioning

MTIA 300 targets recommendation and ranking training: dense MLP operations coexist with sparse embedding-table lookups and updates, frequent cross-device exchanges, and optimizer state. Dense operators benefit from matrix throughput, while sharded embeddings stress HBM bytes, indexed memory access and AllToAllv communication. Consequently, Meta increases memory and networking resources rather than optimizing solely for GEMM FLOPS.

The package couples one large compute chiplet to two network chiplets, each hosting six 800 Gb/s-class RDMA interfaces, together with six HBM3E stacks. The 12×6 active PE grid is supplemented by a redundant row of six repair PEs. Sixteen Message Engines (MEs) offload network and reduction work at the grid edges. Figure 1 is a schematic of these functional resources, not a literal floorplan.

Processing element and asynchronous command execution

Each PE has two 64-byte-wide RISC-V vector cores, a Dot Product Engine (DPE), Reduction Engine (RE), SIMD/Special Function Unit (SFU), Memory Layout Unit (MLU), Command Processor (CP), and Fabric Interface (FI) with DMA. The 512 KB local scratchpad supports circular buffers. RISC-V programs issue work to specialized units through CP while dependency tracking allows compute, layout conversion and DMA to overlap; it is neither a conventional SIMT warp scheduler nor a rack-wide cycle-static Groq-like schedule.

The DPE comprises two 32×64B×32 MAC tiles. It retains one GEMM operand internally while streaming the other from local SRAM for reuse; FP16/BF16 input GEMMs accumulate in FP32. The RE handles results and partial reductions, including across PEs through dedicated reduction connectivity. The SFU handles 128 elements per cycle for elementwise operations, LUT-based functions and stochastic rounding, while MLU handles transpose, reshape and concatenation. The resource-level illustrations in Figures 2–3 do not assert unpublished intra-tile timing.

Sparse embedding gather/scatter and training backward pass

The FI supports indexed DMA to gather and scatter data from an index list stored in PE-local SRAM; byte-aligned data movement, fragmentation and rate shaping support irregular embedding accesses. Backward training benefits from hardware support for radix sort, histogram/bucketization and grouping of updates by index. Figure 3 contrasts these sparse flows with DPE-centric dense computation.

Meta increased SFU throughput relative to MTIA 2i, bringing the reported GEMM-to-SIMD throughput ratio from 32:1 to 16:1. The extra vector bandwidth and indexed movement address workloads for which matrix FLOPS alone are an inadequate architectural proxy.

Memory hierarchy, mesh and recovery

The PE scratchpad is a software-managed 512 KB memory, totaling 36 MB over 72 active PEs. Separate from it is a 192 MB global last-level SRAM split into two 96 MB sides, each consisting of 48 slices of 2 MB. Published descriptions permit global SRAM use as a last-level cache (LLC) or last-level scratchpad (LLS); it must not be described as an invariably hardware-managed LLC. Six 36 GB HBM3E stacks provide 216 GB of off-chiplet capacity and a reported peak 6.1 TB/s.

The compute chiplet uses a 2D mesh with routers serving clusters of six PEs, virtual lanes and dimension-ordered L-routing. Data, control, synchronization and reduction traffic are organized to reduce interference. The mesh handles global-memory selection without the dedicated memory crossbar of earlier MTIA generations. ECC and a redundant PE row provide reliability; the spare row allows replacement of one defective PE in each six-PE column. Quoted local/global SRAM bandwidth is aggregate read-plus-write, while HBM bandwidth uses a read-or-write convention.

Message Engines, NMC reduction and in-package NICs

Sixteen edge-local MEs avoid routing collective calculations through the main DPE/SFU compute grid. Each has a scalar CPU-M RISC-V controller and 256 KB context SRAM, a NIC interface that handles work requests, and near-memory compute (NMC) logic supporting reduction and DMA. An NMC runs at 128 bytes/cycle when isolated or 96 bytes/cycle in a fully concurrent scenario; across all MEs the vendor lists approximately 2.8 TB/s aggregate reduction throughput. This NMC is for communication collectives, not RRAM-style in-memory matrix multiplication.

Two dedicated network chiplets provide twelve 800 Gb/s RDMA NIC interfaces, amounting to 1.2 TB/s aggregate nominal interface capacity. Work requests can be encoded in express doorbells rather than requiring an additional HBM work-queue fetch; Meta reports roughly 800 ns saved per operation. This is distinct from the host PCIe Gen5 x16 connection and from realized fabric bandwidth at rack scale.

HCCL execution graphs and overlapping collectives

Meta HCCL represents collective communication as device-executable dependency subgraphs of work-queue entries (WQEs). A device-side control cluster (CPU-C) issues compute work to PEs and communication subgraphs to ME controllers. MEs autonomously execute communication operations such as SEND, RECV, WRITE and REDUCE with WAIT/SET synchronization and completion tracking. This integrates compute and communication dependency management while retaining independent hardware engines.

Overlapping GEMMs with NMC/RDMA-driven collectives minimizes use of PE arithmetic resources. Meta reports under 0.5% GEMM throughput degradation for the evaluated concurrent-compute scenario, not a universal guarantee. HCCL optimizes collective selection for an asymmetric scale-up/scale-out topology; workload shapes and traffic placement still determine end-to-end performance.

System scale, software stack and deployment

A compute blade pairs one MTIA with a host CPU, typically with 512 GB host RAM. A rack has sixteen compute-blade slots and multiple selectable network-blade configurations. Meta reports approximately 800 GB/s configured scale-up per accelerator within a 16-node rack (potentially 1 TB/s), versus 200 GB/s scale-out per accelerator in a 4,096-node domain. These realized system-network figures must not be equated to the chip's 1.2 TB/s nominal NIC capacity.

The software stack integrates PyTorch and torch.compile, TorchRec, distributed training, Triton and C++ kernels, AOTAutograd and TorchInductor, plus HCCL for collectives. Dense data-parallel training commonly uses gradient AllReduce, whereas sharded embedding training uses AllToAllv to exchange sparse activations and gradients; additional optimizer and sharding strategies can entail AllGather.

Physical design and architectural tradeoffs

The compute chiplet measures 25.6×31.4 mm, joined by two 25.6×9.3 mm network chiplets in a 2.5D CoWoS assembly with a 77.5 mm package. Meta reports 1.9 GHz at 0.85 V, 912 W TDP and 667 W typical power. The publication's 7.2 billion value is a logic-gate count rather than a transistor count. The architectural tradeoff is to allocate substantial silicon and package resources to memory access, reductions and network integration for training throughput.

Why class B2

MTIA 300 uses programmable RISC-V-controlled tensor PEs with local scratchpads, DPE/SFU/MLU/reduction datapaths and separate message-processing engines. These specialized accelerators remain software-programmable rather than a reconfigurable CGRA fabric or a statically scheduled cross-device TSP architecture.

05Notes & references

  • 192 MB is configurable global last-level SRAM (LLC/LLS), separate from 72 × 512 KB PE-local scratchpads (36 MB total). The compute chiplet area excludes NIC chiplets. Optimized for distributed recommendation-model training.
  • Global 192 MB SRAM is configurable as LLC or last-level scratchpad (LLS). The 36 MB total PE-local software-managed SRAM is separate.
  • Six spare PEs are shown dimmed in the 13×6 schematic; the configured active grid has 12×6 PEs.
  • 1.2 TB/s nominal aggregate NIC interface bandwidth differs from configured rack scale-up and scale-out fabric bandwidth.
  • Bandwidth conventions differ: 1.9 TB/s local SRAM and 11.4 TB/s global SRAM use aggregate R+W; 6.1 TB/s HBM uses R or W.
  • 7.2 billion is a published logic gate count, not transistor count. Process node is not disclosed.
  • Message Engine NMC accelerates communication reductions rather than general in-memory matrix operations.
  • Native MX4/NVFP4 GEMM is not available on MTIA 300.
