MTIA 300

B2 B · Tensor-engine-centric — Flexible tensor datapaths

Meta's first training chip in the MTIA line, built for recommendation and generative models. A reticle-size compute chiplet holds a 12×6 grid of processing elements (PEs) — each with two RISC-V vector cores, a dot-product engine, a SIMD engine, reduction and layout units and 512 KB of local memory — plus a 192 MB LLC and 16 message engines. Two network chiplets put twelve 800 Gb/s RDMA NICs inside the package, so collectives never cross PCIe or occupy the compute grid.

02Architectural analysis

Compute organization

The PE is the unit of compute. Its Dot Product Engine (DPE) has two 32 × 64 B × 32 MAC tiles, giving 7.8 TFLOPS per PE at FP16/BF16 input with FP32 output (FP8 and TF32 inputs also supported). Results land in the Reduction Engine (RE), which can also sum partial results across PEs over a dedicated network. A SIMD engine (128 elements/cycle, lookup tables for non-linear functions, stochastic rounding, quantisation) handles element-wise work, and a Memory Layout Unit (MLU) transposes, reshapes, slices and concatenates tensors.

Two 64-byte-wide RISC-V vector cores per PE run control code and custom operators. A Command Processor (CP) dispatches work to the fixed-function units, arbitrates local-memory access and manages circular buffers; a Fabric Interface DMA engine moves data with traffic shaping. Compared with MTIA 2i, the GEMM-to-SIMD throughput ratio drops from 32:1 to 16:1, giving training's element-wise work more headroom.

The 12×6 grid has an extra row of six PEs so each column can tolerate one faulty PE. A quad-core RISC-V control cluster runs the device firmware.

Memory orchestration

Each PE's 512 KB local memory is software-managed (1.9 TB/s read + write). Behind it sits a 192 MB last-level cache split into two sides of 48 × 2 MB slices (11.4 TB/s combined), and six HBM3E stacks (36 GB, 8 Gb/s, ~1 TB/s each) for 216 GB and 6.1 TB/s. SRAM and HBM are ECC-protected.

The atlas does not add PE scratchpad (36 MB in total) to the LLC, because the two behave differently: the database's 192 MB is the LLC only.

Interconnect & system scale

On-die, a 2D mesh with one router per six-PE cluster uses L-routing and virtual lanes for deadlock freedom. Sixteen message engines (MEs) sit in columns of eight along the east and west edges, next to HBM and LLC. Each ME has a scalar RISC-V core with 256 KB context SRAM, a NIC interface and a near-memory-compute block that reduces at 128 B/cycle (2.8 TB/s aggregate) for Reduce, AllReduce and ReduceScatter.

Two network chiplets each carry six 800 Gb/s RDMA NICs (8 × 112G SerDes per chiplet). The same NICs serve scale-up — 800 GB/s per accelerator across a 16-node rack, optionally 1 TB/s — and scale-out at 200 GB/s to a first-level domain of 4,096 nodes. Work requests double as doorbells, saving ~800 ns per operation; concurrent GEMMs and collectives slow compute by under 0.5%.

Programming & scheduling

PyTorch with torch.compile lowers to MTIA kernels; HCCL compiles collectives into subgraphs that run on the MEs, with one-sided and device-triggered communication. Each accelerator is paired 1:1 with a host CPU, which can take optimizer work.

Physical implementation

A 25.6 × 31.4 mm compute chiplet and two 25.6 × 9.3 mm network chiplets sit on a 3.2-reticle CoWoS interposer in a 77.5 mm package: 7.2 billion gates, 1.9 GHz at 0.85 V, 912 W TDP (667 W typical), liquid-cooled. The host link is PCIe Gen 5 x16.

Why class B2

Tensor-oriented PEs with software-managed local memory plus dedicated layout, reduction and DMA engines — a flexible tensor datapath with unusually tight network integration.

05Evidence & caveats

Read before comparing
  • 192 MB is the shared LLC; the 72 PE-local 512 KB scratchpads are separate and not added in. Die area is the compute chiplet. Optimized for recommendation-model training.
  • Process node and transistor count are not given in the paper (it reports 7.2 B gates).
  • MX4 / NVFP4 are not natively supported; Meta says MX4 arrives with MTIA 400.
