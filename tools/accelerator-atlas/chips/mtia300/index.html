MTIA 300

B2 B · Tensor-engine-centric — Flexible tensor datapaths

Meta's MTIA 300 is a training-capable accelerator for recommendation models whose distinguishing feature is networking inside the package: a 12×6 grid of processing elements is flanked by 16 message engines and two network chiplets carrying twelve 800 Gb/s RDMA NICs, so collectives never cross PCIe or occupy the compute grid.

02Architectural analysis

Compute organization

Computation happens on a 12×6 grid of PEs. Communication is handled by 16 dedicated message engines (MEs): each has a RISC-V core for orchestration, an interface that steers requests to the right NIC, and a near-memory compute (NMC) block that performs reductions at 128 bytes per cycle. MEs sit at the die edges next to HBM and cache.

Meta reports that large GEMMs and concurrent collectives slow compute by less than 0.5%, because the PE grid is not involved in communication.

Memory orchestration

Each PE has a local scratchpad (512 KB per the dataset record), backed by a separate shared last-level cache and 216 GB of HBM3E. The atlas deliberately does not add these into one 'SRAM' figure because scratchpad and LLC behave differently.

Interconnect & system scale

Two network chiplets each carry six 800 Gb/s RDMA NICs. The same twelve NICs serve scale-up across a 16-node tier (up to 1 TB/s) and scale-out across racks (200 GB/s), and can be repartitioned between the two without hardware changes. At OCP 2026 Meta described a 51.2T Ethernet scale-up switch (Tahan) for these systems.

Programming & scheduling

PyTorch with Meta's MTIA compiler stack; HCCL collectives run on the MEs. Express doorbells save about 800 ns per communication operation.

Why class B2

Tensor-oriented PEs with local scratchpads plus configurable data-movement engines — a flexible tensor datapath with unusually tight network integration.

05Evidence & caveats

Read before comparing
  • PE-local 512 KB scratchpad and separate shared LLC; avoid reporting a combined SRAM figure. Optimized for recommendation-model training.
  • Process node, power, peak FLOPS, LLC size and HBM bandwidth are not stated in the cited engineering posts (details are in Meta's ISCA '26 paper).
