TPU7x Ironwood

B1 B · Tensor-engine-centric — Structured tensor arrays

Google's seventh-generation TPU, Ironwood, is a two-chiplet package. Each chiplet carries one TensorCore built around systolic matrix-multiply units (MXUs), two SparseCores for embedding-style work, and 96 GiB of HBM; chips are wired into 3D-torus pods of up to 9,216 devices.

02Architectural analysis

Compute organization

A TensorCore combines scalar control, a vector unit and several MXUs — weight-stationary systolic arrays that perform the bulk of the FLOPs. The two chiplets are linked by a die-to-die interface that Google describes as about six times faster than one ICI link.

SparseCores are dataflow processors specialised for gather/scatter-heavy embedding lookups; there are two per chiplet.

Memory orchestration

The TensorCore works out of VMEM, an on-chip SRAM with much higher bandwidth to the MXUs than HBM. VMEM is allocated by the XLA compiler (its usable size is a tunable compiler parameter, not a fixed public number), so data movement between HBM and VMEM is explicit in the compiled program rather than handled by caches.

Interconnect & system scale

Six inter-chip-interconnect (ICI) links provide 1.2 TB/s per chip. Chips form 4×4×4 cubes; optical circuit switches stitch cubes into 3D tori for slices of 64 chips and up, to a maximum of 9,216. Each group of four chips attaches to a host CPU over PCIe; data-centre networking (DCN) handles traffic between pods.

Programming & scheduling

JAX and PyTorch (via XLA). The compiler statically tiles and schedules matrix work onto MXUs and inserts DMA between HBM and VMEM; collectives map onto the torus.

Why class B1

Large systolic matrix engines dominate computation, with structured, compiler-managed tiling and VMEM staging — the structured-tensor-array subclass.

05Evidence & caveats

Read before comparing
  • 192 GiB HBM according to cloud docs; represented numerically as 192 (GiB differs from GB). VMEM capacity not fixed in public product table.
  • 192 GiB is binary (GiB); the dataset stores 192 in a GB column. Frameworks report slightly less because the system reserves part of HBM.
  • MXU size/count and power are not stated in the cited Cloud TPU documentation.
